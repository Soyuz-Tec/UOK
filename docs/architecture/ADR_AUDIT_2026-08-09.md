# UOK ADR Re-evaluation — 2026-08-09

## Scope and method

All ADR files, their repository references, current source boundaries, tests,
CI controls, operations documents, and the protected-main baseline were
re-evaluated. The audit separates decision acceptance from implementation and
production activation. Repository and runtime evidence outrank historical
test counts or branch/PR wording inside older ADRs.

## Material conclusions

UOK is a modular monolith, not a micro-frontend or microservice system.
ADR-0036 records the isolation it can truthfully claim today: a React render
exception inside an already-loaded module surface is contained by that
surface's error boundary, while health probes support removal or restart of an
unready API instance. The current eager frontend bundle, shared JavaScript
realm, single Python process, single worker, and shared database do not provide
independent process failure domains.

The Planning transactional outbox in ADR-0019 is durable same-transaction
commit evidence only. It is not a centralized event-driven core and has no
dispatcher, delivery state, retry lease, dead-letter policy, or consumer
reconciliation contract. ADR-0042 is intentionally Proposed until those
semantics are reviewed and implemented.

No Rust rewrite is justified by the reviewed ADR evidence. UOK's current
Python/TypeScript/PostgreSQL stack remains authoritative. Rust would require a
specific measured bottleneck or isolation need, a bounded component proposal,
and a separate accepted ADR with build, security, deployment, observability,
and rollback evidence.

## Remaining gates

- Accept or reject Proposed ADR-0037 through ADR-0043 before implementation.
- Complete the activation evidence in ADR-0031 before enabling RLS.
- Execute and verify a protected prerelease before promoting ADR-0033 from
  Partial to Implemented in release operations.
- If UOK needs stronger fault isolation than ADR-0036 provides, select an
  explicit process/deployment boundary and validate it with fault injection.
- Replace stale fixed test-count and branch/PR statements in operational
  traceability with current generated evidence; historical ADR prose remains
  preserved unless a new decision supersedes it.
