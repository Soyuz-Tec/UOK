# ADR-NNNN: Decision Title

**Status:** Proposed

**Implementation status:** Planned

**Date:** YYYY-MM-DD

**Owners:** Named accountable maintainers

**Relations:** None, or identify the ADRs this decision amends, supersedes, or depends on

## Context

Describe the forces, current repository/runtime facts, quality attributes, and
the decision that must be made. Separate verified current behavior from desired
behavior.

## Decision

State one material decision. Define ownership, boundaries, data or API
contracts, failure behavior, security controls, and activation gates where they
matter. Do not use Accepted to imply that unimplemented behavior is live.

## Consequences

Record benefits, costs, risks, operational effects, and remaining limitations.

## Alternatives

List the serious alternatives considered and why they were not selected.

## Validation

Name executable tests, runtime evidence, deployment proof, or review evidence
that can demonstrate implementation. An Accepted decision may still be
Planned, Partial, or Inactive in the registry.

## Rollback

Explain how to disable or reverse the implementation safely. If rollback is
not applicable, state why.

## Revisit triggers

List measurable changes that require the decision to be reviewed.
